# 2026-09-12 — The designer's second pass lands, and the form turns out never to have worked

**Source**: five commits, `59205a4` through `8490253` (20:24–21:25); pull requests [#8](https://github.com/ASO-DB-Solutions/site-datacaddy/pull/8) and [#9](https://github.com/ASO-DB-Solutions/site-datacaddy/pull/9). Several findings came from probing the live site and the Microsoft tenant rather than from the repository, and are recorded here because they changed what was built.

Two things happened today. Nina's second design pass was brought in and is live. And the contact
form, which yesterday's entry described as working and merely un-notified, turned out never to
have accepted a single submission.

## The form has been discarding everything since launch

The owner filled in the form and got an error. Investigating it produced a plain answer and an
uncomfortable one.

**Netlify turns form detection off by default** on every site created since April 2023, to keep
builds fast. With it off, the build-time scan that registers a form never runs, so the site
answers every submission with a 404 — the same response it gives for a form that was never
written. Nothing was captured. The owner's test is gone, and so is anything a real visitor sent.

The uncomfortable part is that yesterday's documentation said the opposite. It stated the form was
"built, deployed and detected", and sent the owner to look for submissions waiting in a dashboard
that has never held any. Two checks had been run and both passed: the endpoint was live, and the
hidden form markup was present in the published page. Neither says anything about whether the form
is *registered*, which is the thing that actually matters.

Both guides, the stakeholder note and the project's own memory were corrected. Enabling detection
is now the first step rather than an afterthought, and it carries the redeploy that enabling alone
does not do — the setting applies only to future publishes, never to the build already live.

## Nina's design is in

Her export changed one file and two images. The navigation now stays fixed at the top and grows a
blurred background as the page scrolls; the hero artwork is sized and centred differently; the
cost calculator gained **Oracle Cloud and Google Cloud** alongside AWS and Azure; and the contact
form was redesigned with a two-column layout, clearer required markers and a warmer confirmation.

Her contact form, however, **sends nowhere**. It shows "We got your message" over a discarded
payload — there is no code behind the button. So the two versions were combined: her design and
labels, which are better than ours, on top of the machinery that actually delivers a message.

One of her additions was deliberately left out. She added a **"Sign in"** link pointing at a bare
IP address over an unencrypted connection. Linking a sign-in page that way from a secure site
means anything typed there travels in the clear, and publishing the address puts infrastructure on
a public page. A proper address and certificate are being arranged; the link goes in when they
exist.

## A recurring problem got a decision record rather than another fix

The calculator identified each cloud by the words printed on its button. Editing that label — an
ordinary copy change — would silently switch which cloud's prices were shown. The same shape
arrived in the first export, was fixed, and came back in this one, because a designer working in
Figma has no way to know a caption is load-bearing.

It is now impossible: the code identifies clouds by short internal codes, and the visible names
live in one place that anyone may edit freely. **The compiler caught a leftover comparison the
moment the change was made** — a hard error at the exact line, where before it would have been a
condition that is quietly never true.

Worth noting for the third time this week: the build succeeded while that check failed. A
successful build does not mean the code is correct, and this project gates on the stricter check
for exactly that reason.

## Three things nobody could see

The design change went live **without anyone having looked at it**. A preview was published for
review, but Netlify serves previews only to the account owner on the current plan, so neither the
owner nor the designer could open it. The decision was to proceed anyway, which is defensible
here: the previous version is tagged, kept on a branch, and recoverable from Netlify's own deploy
history in seconds. The setting that would have allowed review is recorded for next time.

Separately, three verification attempts today reported confident answers from checks that were not
measuring anything: a preview page that was really a login screen, a search of a compiled file for
text the compiler had rewritten, and — yesterday — a web address containing a wildcard that fetched
nothing at all. Each returned "zero occurrences", which reads identically to a clean result. The
habit worth keeping is to confirm the check reached its target before believing what it reports.
